# PC 로그인 화면 — 이대로 만듭니다

> **AI 에게** — PC 웹에서 아이디·비밀번호 로그인 화면을 만들거나 고칠 때 이 한 장을 먼저 읽습니다.
> 모바일 로그인은 `login.mobile.md` 입니다. 섞지 않습니다.
> 원본: S1-UX-DESIGN-with-AI `registry/patterns/pc-login` (river 승인 2026-10-02). 원본이 바뀌면 이 파일도 다시 옮깁니다.

## 1. 화면 뼈대

위에서 아래로 쌓습니다. 화면 바탕은 `--color-bg-level-0`.

| 순서 | 자리 | 무엇 |
| --- | --- | --- |
| 1 | 맨 위 줄 | Login GNB — 높이 56. 왼쪽 `[서비스명]`, 오른쪽 언어(`한국어`). 배경 `--color-navigation-bg` · 글자 `--color-text-title-primary` · 아이콘 `--color-icon-gray` |
| 2 | 본문 | 남는 높이 전부. 위 여백 123, 가로 가운데에 **로그인 묶음** 하나뿐 |
| 3 | 맨 아래 띠 | Footer — 서비스의 회사 정보 띠 |

- 원본 디자인의 브라우저 창틀(Web Tab Bar)은 실제 브라우저가 그려 주므로 **만들지 않습니다.**
- Login GNB · Footer · CI 는 배포본(`ui-library/dist`)에 아직 없습니다. 위 토큰으로 직접 만들되, 색·글자는 토큰만 씁니다. 로고(CI)는 서비스가 가진 에스원 로고 파일을 씁니다.

## 2. 로그인 묶음

폭 300, 세로로 쌓고 가운데 정렬. 간격은 그대로 지킵니다.

```
CI(에스원 파랑 로고)
  ↓ 34
아이디 입력칸
  ↓ 10
비밀번호 입력칸
  ↓ 32
로그인 버튼 (폭 300 꽉 채움)
  ↓ 16
보조 링크 줄
```

| 무엇 | 부품 · 예제 | 크기 |
| --- | --- | --- |
| 아이디 칸 | `input` — `examples/input.html` | `md` (44) |
| 비밀번호 칸 | `input` 비밀번호 — `examples/input.password.html` (보기 아이콘 켬) | `md` (44) |
| 로그인 버튼 | `button` primary — `examples/button.html` | `md` |
| 보조 링크 | `text-button` secondary — `examples/text-button.html` | — |

- **로그인 화면은 화면 종류(PR용·사용자용·관리자용)와 상관없이 위 크기로 고정**합니다. `profile.*.md` 크기표를 적용하지 않습니다.
- 입력칸에는 위 라벨을 달지 않고, 안내 문구(placeholder)와 `aria-label` 로 이름을 줍니다.
- 보조 링크 줄: 가로 한 줄 · 가운데 정렬 · 항목 사이 12. 링크 사이 구분선은 1×12, 색 `--color-line-default`. 서비스가 링크를 빼면 짝이 되는 구분선도 함께 뺍니다(줄 끝에 구분선이 남지 않게).

## 3. 화면 상태 7개

| 번호 | 상태 | 아이디 칸 | 비밀번호 칸 | 로그인 버튼 |
| --- | --- | --- | --- | --- |
| 1 | 최초 진입 | 빈칸 | 빈칸 | 꺼짐(`disabled`) |
| 2 | 아이디 입력 중 | 포커스 · `s1desig` | 빈칸 | 꺼짐 |
| 3 | 비밀번호 입력 중 | `s1design` | 포커스 · `••••••••` | 켜짐 |
| 4 | 입력 완료 | `s1design` | `••••••••` | 켜짐 |
| 4a1 | 계정 불일치 | 오류 · 문구 없음 | 오류 · 문구 A | 켜짐 |
| 4a2 | 5회 실패 잠금 | 오류 · 문구 없음 | 오류 · 문구 B | 켜짐 |
| 4a3 | 사용 중지된 계정 | 오류 · 문구 없음 | 오류 · 문구 C | 켜짐 |

- 실패 분기 `4a*` 는 모두 4(로그인 실행 → 서버 판정)에서 갈라집니다.
- 사용자가 값을 고치면 4 와 같은 상태로 돌아갑니다. 복귀용 화면은 따로 두지 않습니다.
- 오류 표시: 두 칸 모두 `control` 에 `aria-invalid="true"`. 문구는 비밀번호 칸의 `message` 에 **한 번만** 넣고 `aria-describedby` 로 잇습니다. 아이디 칸에는 `message` 를 두지 않습니다.

## 4. 반드시 지킬 규칙

1. 아이디나 비밀번호가 비어 있으면 로그인 버튼은 꺼 둡니다. 둘 다 차면 켭니다.
2. 아이디·비밀번호 형식을 입력 중에 검사하지 않습니다. 빈칸 제출 후 오류 화면도 만들지 않습니다.
3. 로그인 실패는 서버 응답 뒤 **하나의 통합 오류**로 보여 줍니다. 어느 값이 틀렸는지, 계정이 있는지 드러내지 않습니다.
4. 실패 안내를 로그인 묶음 위 빨간 상자로 따로 띄우지 않습니다. 잠금·사용 중지도 같은 자리·같은 방식이고 문구만 다릅니다.
5. 비밀번호는 가리고(`type="password"`), 보기 아이콘을 켭니다.

## 5. 문구

| 자리 | 문구 |
| --- | --- |
| 아이디 안내 | `아이디를 입력해 주세요.` |
| 비밀번호 안내 | `비밀번호를 입력해 주세요.` |
| 로그인 버튼 | `로그인` |
| 보조 링크 | `회원가입` · `아이디 찾기` · `비밀번호 찾기` |
| 문구 A (불일치) | `아이디 또는 비밀번호가 없거나 잘못 입력되었습니다.` 줄바꿈 `확인 후 다시 로그인 해주세요. (1/5)` |
| 문구 B (5회 잠금) | `아이디 또는 비밀번호가 없거나 잘못 입력되었습니다.` 줄바꿈 `확인 후 다시 로그인 해주세요.(최대 5분)` |
| 문구 C (사용 중지) | `사용이 중지된 계정입니다. 관리자에게 문의해 주세요.` |

- 문구는 글자 그대로 씁니다. B 의 `해주세요.(최대 5분)` 괄호 앞 붙여쓰기도 원문 그대로입니다(river 확정 2026-10-02).
- 두 줄 문구가 잘리거나 접히지 않게 문구 자리는 가로로 꽉 채우고 높이는 내용만큼 늘립니다.

## 6. 서비스마다 바꿔도 되는 것

- `[서비스명]`
- 보조 링크의 종류·개수(빼면 구분선도 함께)
- 재시도 횟수(`5`)·잠금 시간(`5분`)의 숫자
- 로그인 성공 후 이동할 곳

바꾸더라도 4번 규칙은 유지합니다. 계정이 있는지 드러내거나 어느 값이 틀렸는지 단정하는 문구로 바꾸지 않습니다.
