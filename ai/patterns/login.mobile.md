# 모바일 로그인 화면 — 이대로 만듭니다

> **AI 에게** — 모바일 앱에서 아이디·비밀번호 로그인 화면을 만들거나 고칠 때 이 한 장을 먼저 읽습니다.
> PC 로그인은 `login.pc.md` 입니다. 섞지 않습니다.
> 원본: S1-UX-DESIGN-with-AI `registry/patterns/mobile-login` (기준 서비스 MoDU App, river 승인 2026-08-25). 원본이 바뀌면 이 파일도 다시 옮깁니다.

## 1. 화면 뼈대

| 순서 | 자리 | 무엇 |
| --- | --- | --- |
| 1 | 맨 위 | 휴대폰 상태 표시줄 — 기기가 그려 주므로 **만들지 않습니다** |
| 2 | 본문 | 로고(CI) → 아이디·비밀번호 입력칸 → 로그인 버튼 → 보조 링크 줄 → `휴대전화번호로 로그인` |
| 3 | 맨 아래 | Footer — 서비스의 회사 정보 띠 |

- 입력칸·버튼·링크 줄 폭은 320, 가운데 정렬.
- 입력 중 키보드는 기기가 띄우므로 그리지 않습니다. 다만 **키보드가 열려도 로그인 버튼과 보조 링크가 가려지거나 겹치지 않게** 합니다.
- CI · Footer 는 배포본(`ui-library/dist`)에 아직 없습니다. 색·글자는 토큰만 쓰고, 로고는 서비스가 가진 에스원 로고 파일을 씁니다.

| 무엇 | 부품 · 예제 | 크기 |
| --- | --- | --- |
| 아이디 칸 | `input` — `examples/input.mobile.html` | `md` |
| 비밀번호 칸 | `input` 비밀번호 — `examples/input.password.mobile.html` (보기 아이콘 켬) | `md` |
| 로그인 버튼 | `button` primary — `examples/button.mobile.html` | `lg` |
| 보조 링크 | `text-button` — `examples/text-button.html` | — |
| 안내 팝업 | `modal` — `examples/modal.mobile.html` | — |

- 보조 링크 줄(`회원가입` · `아이디 찾기` · `비밀번호 찾기`): 가로 한 줄 · 가운데 정렬. 구분선은 Footer 구분선과 같은 규격 — 1×10, 좌우 여백 8, 색 `--color-line-default`. 링크를 빼면 짝이 되는 구분선도 함께 뺍니다.

## 2. 화면 상태 10개

**기본 흐름**

| 번호 | 상태 | 모습 |
| --- | --- | --- |
| 1 | 최초 진입 | 두 칸 빈칸, 로그인 버튼 꺼짐 |
| 2 | 아이디 입력 중 | 아이디 포커스, 비밀번호 빈칸, 로그인 꺼짐, 키보드 열림 |
| 3 | 비밀번호 입력 중 | 아이디 `s1design`, 비밀번호 포커스·가림, 로그인 켜짐, 키보드 열림 |
| 4 | 입력 완료 | 두 칸 모두 입력, 키보드 닫힘, 로그인 켜짐 |

**분기 — 모두 4(로그인 실행 → 서버 판정)에서 갈라집니다**

| 번호 | 무엇 | 모습 |
| --- | --- | --- |
| 4a1 | 계정 불일치 | 두 칸 오류 테두리, 비밀번호 칸 아래 통합 오류 문구 + 시도 횟수 |
| 4b1 | 자동 로그인 질문 | 팝업 · 버튼 2개 |
| 4b2 | 자동 로그인 설정 완료 | 팝업 · 버튼 1개 |
| 4c1 | 본인 인증 안내 | 팝업 · 버튼 1개 |
| 4c2 | 기기 인증 완료 | 팝업 · 버튼 1개 → 확인하면 4 로 돌아감 |
| 4c3 | 기기 등록 안내 | 팝업 · 버튼 2개 |

- 4c(새 기기) 세 팝업은 항상 순서대로 다 나오는 게 아닙니다. 서버 응답과 서비스 정책에 맞는 것만 씁니다.
- **팝업 뒤 배경은 4(입력 완료)와 완전히 같아야** 합니다. 가려져도 문구·상태가 같아야 합니다.
- 오류 표시: 두 칸 모두 `control` 에 `aria-invalid="true"`. 문구는 비밀번호 칸 `message` 에 **한 번만** 넣고 `aria-describedby` 로 잇습니다.

## 3. 반드시 지킬 규칙

1. 아이디나 비밀번호가 비어 있으면 로그인 버튼은 꺼 둡니다(2026-08-21 river 결정). 빈칸 오류 화면은 만들지 않습니다.
2. 아이디·비밀번호 형식을 입력 중에 검사하지 않습니다.
3. 로그인 실패는 서버 응답 뒤 **하나의 통합 오류**로. 어느 값이 틀렸는지, 계정이 있는지 드러내지 않습니다.
4. 비밀번호는 가리고 보기·숨기기 버튼을 둡니다(버튼에 읽을 수 있는 이름 포함 — 예제에 들어 있음).
5. 자동 로그인은 미리 켜 두지 않습니다. 사용자가 팝업에서 직접 고르게 합니다.
6. 새 기기는 서비스 정책에 맞는 인증·등록 안내를 거칩니다. 인증 완료와 로그인 완료를 같은 뜻으로 쓰지 않습니다.

## 4. 팝업 규칙

- 모바일 `modal` 을 씁니다. 360 화면에서 팝업 폭 300, 좌우 여백 30.
- 본문 높이는 내용만큼. 빈 공간을 만드는 고정 높이를 두지 않습니다.
- 알림만 하면 버튼 1개, 고르게 하면 버튼 2개(`아니오` / `네`).
- 긴 문구가 잘리거나 버튼과 겹치지 않게 합니다.

## 5. 문구

| 자리 | 제목 | 본문 | 버튼 |
| --- | --- | --- | --- |
| 4a1 오류 | — | `아이디 또는 비밀번호가 없거나 잘못 입력되었습니다.` 줄바꿈 `확인 후 다시 로그인 해주세요. (1/5)` | — |
| 4b1 | `자동 로그인 안내` | `다음부터 자동으로 로그인할까요?` | `아니오` / `네` |
| 4b2 | `자동 로그인 설정 완료` | `자동 로그인이 설정되었어요.` | `확인` |
| 4c1 | `본인 인증 안내` | `서비스를 이용하려면 본인 인증을 진행해 주세요. 본인 인증 시 기존 기기는 인증이 해제돼요.` | `확인` |
| 4c2 | `기기 인증 완료` | `사용 중인 기기로 인증이 완료됐어요.` 줄바꿈 `다시 로그인해 주세요.` | `확인` |
| 4c3 | `기기 등록 안내` | `에스원은 고객님의 소중한 정보를 보호하기 위해 인증 기기 등록 후 서비스를 제공하고 있어요.` 줄바꿈 `현재 인증한 기기로 등록 후 로그인할까요?` | `아니오` / `네` |

- 입력칸 안내: `아이디를 입력해 주세요.` · `비밀번호를 입력해 주세요.` / 로그인 버튼: `로그인`
- 다른 로그인 수단 버튼: **`휴대전화번호로 로그인`** — 모든 화면 같은 문구(`휴대폰 번호로 로그인` 은 쓰지 않음, river 확정 2026-08-25).

## 6. 서비스마다 바꿔도 되는 것

- 로고와 서비스명
- 회원가입·아이디 찾기·비밀번호 찾기 링크의 제공 여부
- 추가 인증 수단의 이름, 새 기기 안내 문구
- 로그인 성공 후 이동할 곳

바꾸더라도 3번 규칙은 유지합니다. 버튼 문구는 누르면 무슨 일이 생기는지 알 수 있는 말로 씁니다.

## 7. 만들지 않는 것
