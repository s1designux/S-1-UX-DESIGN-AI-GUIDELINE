# 이미 있는 화면(POC)에 S1 입히기

> 온보딩 Q0 에서 **"이미 있는 화면에 입히기"** 를 골랐을 때만 읽습니다.
> 핵심: **바꾸기 전에 디자인 확인 요청서를 먼저 만들어 디자이너에게 보냅니다.** 디자이너 답을 받기 전에는 화면을 고치지 않습니다.

새로 만들 때와 다른 점은 하나입니다. POC 에는 이미 개발자가 만든 버튼·입력칸·팝업이 있고, 이름이 제각각입니다.
그래서 **"이건 S1 의 어떤 부품인가"** 를 먼저 짝지어야 합니다. 짝짓는 기준(언제 쓰나·쓰지 말 때)은 디자인에 있으므로, 애매한 것은 디자이너가 정합니다.

## 1단계 — POC 부품 목록 뽑기

온보딩에서 정한 화면 범위의 파일을 훑어 **화면에 보이는 부품을 빠짐없이** 적습니다.
버튼·입력칸·선택 상자·날짜·표 자체·탭·팝업·상태 표시·켜고 끄기·경로 표시·진행 막대 등, 사람이 보고 누르거나 읽는 것 전부입니다.

- **같은 것이 여러 번 나오면 한 항목**으로 적습니다(예: 줄마다 있는 삭제 버튼). 모습이나 뜻이 다르면 따로 적습니다(예: 초록 '정상' 표시와 빨간 '거부' 표시).
- 제목·본문 같은 **글자만 있는 것은 적지 않습니다.** 글자는 S1 글자 크기·색으로만 맞춥니다.

부품마다 이것을 적습니다.

- **하는 일** — 이 부품이 화면에서 무슨 일을 하는가(예: "조건으로 목록을 다시 불러온다"). **이름은 믿지 않습니다.** `btn-primary` 가 실제로는 보조 동작일 수 있습니다.
- **모습** — 색·크기·모양이 눈에 띄면 짧게(예: "빨간 배경 작은 버튼").
- **자리** — `form`(폼·상세 본문) · `header`(페이지 제목 줄) · `filter`(검색·필터 줄) · `table`(표와 표 칸 안) · `popup`(팝업 본문). 어디에도 딱 맞지 않으면 `form` 입니다.
- **어디** — 파일과 줄 번호, POC 마크업 한 토막, 화면에서 그 부품을 찾는 **CSS 선택자**(`selector`, 같은 것이 여러 개면 모두 표시되고, 하나만 가리키려면 `nth`)

## 2단계 — 하는 일로 S1 부품 짝짓기 → 대응표

`ai/generated/matching-guide.<pc|mobile>.md` 의 **언제 쓰나 / 쓰지 말 때** 로 고릅니다. 크기는 온보딩에서 고른 화면 종류의 크기표(`ai/generated/profile.<종류>.md`)에서 자리별로 가져옵니다.

결과는 세 가지 중 하나입니다.

| 판정 | 뜻 | 예 |
| --- | --- | --- |
| `exact` ✅ | 하는 일과 모습이 S1 부품과 맞는다 | 주 액션 버튼 → `button` primary |
| `similar` 🟡 | 하는 일은 맞는데 모습·변형이 S1 에 없다 | 빨간 삭제 버튼 → S1 버튼에 빨간색 없음 |
| `none` ❌ | 맞는 S1 부품이 없다 | 경로 표시(브레드크럼), 진행 막대 |

**없는 부품을 지어내지 않습니다.** `none` 은 그대로 `none` 으로 둡니다.

POC 폴더 맨 위에 `s1-mapping.json` 으로 저장합니다. 본보기: `ai/fixtures/poc-sample/s1-mapping.json`

```json
{
  "project": "출입관리 POC",
  "profile": "admin",
  "createdAt": "2026-10-02",
  "requestedBy": "홍길동(개발)",
  "items": [
    {
      "id": "P01", "screen": "출입 기록 관리", "file": "src/list.html", "line": 12, "zone": "header",
      "selector": "#btnNew", "url": "(선택) 실행 중인 화면 주소 — 없으면 file 을 연다",
      "poc": { "name": "btn btn-primary", "does": "새 기록 등록 화면을 연다 — 주 액션", "looks": "파란 버튼", "markup": "<button class=\"btn btn-primary\">등록</button>", "image": "(선택) 잘라낸 화면 그림 경로" },
      "match": "exact",
      "s1": { "component": "button", "variant": "primary", "size": "xsm", "label": "등록" },
      "alternatives": [],
      "why": "matching-guide 의 button '언제 쓰나' — 화면에서 가장 중요한 단일 액션은 primary",
      "gap": "(similar·none 일 때 필수) 무엇이 다른지"
    }
  ]
}
```

- `id` 는 겹치지 않게 `P01`, `P02` … 로 붙입니다.
- `similar`·`none` 은 `gap` 을 꼭 적습니다 — 디자이너가 이것을 보고 고릅니다.
- 후보가 둘 이상이면 `alternatives` 에 더 넣습니다(예: 목록 조건 고르기 → `select` 또는 `filter-chip`).
- 크기표에서 그 자리·그 부품 칸이 `—`(기준 없음)이면 크기를 비워 두고(`size` 생략 = 예제 크기) `why` 에 "이 자리 크기 기준 없음"이라고 적습니다. 디자이너가 요청서에서 봅니다.
- 승인 전 후보 부품(scope.json 의 `status: candidate`)도 제안할 수 있습니다. 요청서에 "승인 전 후보"로 표시됩니다.

## 3단계 — 화면 캡처 → 디자인 확인 요청서 만들어 보내기

디자이너는 **화면을 보고** 어떤 부품으로 바꿀지, 새로 만들지 정합니다. 그래서 부품마다 주변이 보이게 넓게 찍어 요청서에 넣습니다.

```bash
python3 <S1 가이드 폴더>/ai/scripts/capture-poc.py <POC폴더>/s1-mapping.json
node <S1 가이드 폴더>/ai/scripts/review-request.mjs <POC폴더>/s1-mapping.json
```

- 첫 줄이 부품마다 빨간 테두리를 친 넓은 캡처(`s1-captures/P01.png` …)와 화면 전체 번호판을 찍고, 대응표에 그림 경로를 적어 넣습니다. Playwright 가 필요합니다(`pip install playwright && python3 -m playwright install chromium`).
- Playwright 를 쓸 수 없으면 AI 도구의 브라우저 캡처로 찍어 `poc.image` 에 경로를 직접 적습니다. 캡처가 하나도 없으면 요청서에 "화면 캡처가 없습니다"라고 나옵니다 — **가능하면 꼭 찍습니다.**
- 로그인이 필요한 화면은 항목에 `url` 을 적고, 로그인된 상태의 개발 서버 주소를 씁니다.

`<POC폴더>/디자인확인요청서.html` 한 장이 생깁니다. 왼쪽에 지금 POC 모습, 오른쪽에 바꿀 S1 부품이 실제 모양으로 그려집니다.
대응표 형식이 틀리면 스크립트가 무엇을 고칠지 알려 주고 요청서를 만들지 않습니다.
화면을 볼 수 있는 도구라면 요청서를 한 번 열어 부품이 제대로 그려졌는지 보고, **이 파일을 디자이너에게 보냅니다.**

여기서 **멈춥니다.** 디자이너 답을 받기 전에 POC 를 고치지 않습니다. 사용자에게 "디자인 확인 요청서를 디자이너에게 보내 주세요"라고 알립니다.

## 4단계 — 디자이너 답 받기

디자이너는 요청서에서 항목마다 고르고 **결과 복사** 를 눌러 개발자에게 보냅니다.
개발자가 붙여 준 글(JSON)을 POC 폴더 맨 위에 **`s1-review-result.json`** 으로 그대로 저장합니다.

| 디자이너 답 | 할 일 |
| --- | --- |
| `apply` | 대응표의 `s1` 부품으로 바꿉니다 |
| `alt:N` | 대응표 `alternatives[N]` 부품으로 바꿉니다 |
| `keep` | 바꾸지 않습니다. 그 요소에 `data-s1-keep="<id>"` 를 달고, 색·글자만 S1 토큰으로 맞춥니다 |
| `request` | `keep` 과 같이 두고 `data-s1-keep="<id>"` 를 답니다. 디자인 시스템에 새로 만들 부품 목록이 됩니다 |

메모가 있으면 메모를 따릅니다. 답이 비어 있는 항목은 바꾸지 말고 사용자에게 묻습니다.

## 5단계 — 바꾸고 검수

- 바꿀 부품은 `ui-library/dist/examples/` 마크업을 그대로 쓰고, 기존 동작(이벤트·데이터 연결)은 새 부품에 다시 이어 줍니다.
- 자리 표시: 제목 줄은 `data-s1-zone="header"`, 검색·필터 줄은 `data-s1-zone="filter"`. 화면 맨 바깥에 `data-s1-density` (크기표 1번).
- 검수기는 `s1.profile.json` 과 `s1-review-result.json` 을 읽습니다. `data-s1-keep` 은 디자이너가 `keep`·`request` 로 정한 id 만 예외로 인정하고, 그 밖의 예외는 불합격입니다.

```bash
node <S1 가이드 폴더>/ai/check/s1-check.mjs <POC폴더> --report <POC폴더 밖>/판정표.html
```

합격하기 전에는 "다 입혔다"고 말하지 않습니다. 끝나면 사용자에게 **새 부품 요청(`request`) 목록**을 함께 알려 줍니다.
